# 1f6s Desktop

[![build](https://github.com/brnme/1f6s-desktop/actions/workflows/build.yml/badge.svg)](https://github.com/brnme/1f6s-desktop/actions/workflows/build.yml)

[English](README.md) | [中文](README-zh.md)

Desktop client of the [1f6s compression initiative](https://github.com/brnme/1f6s). It shrinks hours-long screen recordings into small MP4 files that fit e-mail attachments and LMS upload limits — entirely on your machine. ffmpeg runs locally as a subprocess; recordings never leave the computer.

Compression parameters are the same as on the [web service](https://1f6s.com): the eight-level specification is synced from the server repo into `assets/spec/`, and command construction is verified token-by-token against 261 golden-vector cases generated by the web service's own Python code, so desktop and web produce identical ffmpeg commands for the same input.

## Highlights

- **Three ways to pick settings**
  - *Level* — choose one of the eight levels L1–L8 directly (L4 is the default).
  - *Scene* — pick what the video is for (e-mail, instant messaging, training, MOOC, demo, compliance, offline viewing, platform upload, archive) and the matching level is applied.
  - *Fine-tune* — start from a baseline level and override resolution (720p/480p/360p), frame interval, grayscale, and audio bitrate.
- **Batch queue** — picked files wait in a staging list and only run after you press *Start compression*; each row shows live progress parsed from ffmpeg, and can be removed (queued) or cancelled (running). The output is written next to the source as `<stem>_1f6s.mp4` and never overwrites the original.
- **Splitting** — cut oversized recordings into parts that fit the service's upload tiers (2048 / 5120 / 8192 MB, or a custom size), with a pre-flight check that rejects inputs the transcode could not finish in time.
- **English and 中文 UI**, switchable in Settings (also: low-priority mode, thread cap, preset speed, custom ffmpeg/ffprobe paths).
- **Spec update check** — the About page quietly asks `1f6s.com` whether a newer level specification has been published.

## The eight levels

| Level | Name | Notes |
| --- | --- | --- |
| L1 | Standard | Colour, 480p; a 99-minute recording ≈ 30–35 MB |
| L2 | Grayscale | Black & white |
| L3 | High compression | |
| L4 | Smart tuning | Default; ≈ 16–19 MB per 99 minutes |
| L5 | Audio extreme | |
| L6 | Long interval | 360p, one frame every 10 s |
| L7 | Exact size | Two-pass, locks the output to a target size (1–500 MB) |
| L8 | H.265 extreme | ≈ 6–8 MB per 99 minutes |

The authoritative definitions live in `assets/spec/levels.json`; the table above is a quick reference.

| Package | Baseline |
| --- | --- |
| `1f6s-desktop-0.1.0-x86_64.AppImage` | Linux, glibc 2.31+ (Ubuntu 20.04+) |
| `1f6s-desktop-0.1.0-x86_64.dmg` | macOS 10.15+ (Intel) |
| `1f6s-desktop-0.1.0-win64.zip` | Windows 10+ (x64), portable — unzip and run |

The Windows zip and Linux AppImage bundle ffmpeg/ffprobe; the macOS dmg bundles them as well. Binaries are not code-signed: on macOS right-click → *Open* the first time, and on Windows click *More info → Run anyway* if SmartScreen warns.

## Building from source

Requires Qt 6.2+, CMake ≥ 3.16, and Ninja. ffmpeg/ffprobe must be on `PATH` (or set explicit paths in the app's Settings).

```bash
cmake -B build -G Ninja -DCMAKE_PREFIX_PATH=/path/to/Qt/6.2.4/gcc_64
cmake --build build
ctest --test-dir build   # optional; ffmpeg-dependent cases skip themselves if engines are missing
./build/1f6s-desktop
```

Tooling used to sync the specification and regenerate the golden vectors from the web-service repo:

```bash
tools/sync_spec.sh     # sync level/precheck/tier parameters from the website repo → assets/spec/
tools/gen_vectors.py   # regenerate the golden vectors → vectors/vectors.json
```
